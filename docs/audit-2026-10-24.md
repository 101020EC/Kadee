## Decisions

- **D1 (B4)**: Several people use Kadee. The proposer name and position are personal: they live in
  each machine's `localStorage` only. The client stops sending them to `/api/vis-settings`, the
  server stops writing them, and the mount effect stops reading them from the cloud. Approver names
  and the MY VIS officer names stay shared through `settings/vis`.
- **D2 (B4)**: The approver choice (ฝคต. / ฝปป., `approver_selection`) is personal too, so it is
  also stored in `localStorage` only. Each officer sends memos to their own department head. Both
  approver names (`approver_1_name`, `approver_2_name`) stay shared in the cloud.
- **D3 (B5)**: Shared settings stay open, with no password, because anyone may need to fix a name.
  Instead, every save that changes a shared name sends a Telegram message. The message lists only the
  fields that changed, as `old → new`. It also names who saved: the client sends that machine's local
  proposer name as `changed_by`, used only in the notification and never stored. The server reads the
  current `settings/vis` before writing to compute the diff. A save with no changes sends nothing.
- **D4 (B1, B7)**: `fine_amount_th` is recomputed every time `fine_amount` changes, but the field
  stays editable so the user can type over it. Move `thaiBahtText` to a shared module used by both
  `api/upload` and `page.js`. Fix the reading so a trailing 1 after a zero becomes `เอ็ด`
  (101 → หนึ่งร้อยเอ็ด), and return an empty string for NaN. `fine_amount` is **not** recomputed
  when `fine_days` changes, because the receipt amount is what was actually paid.
- **D5 (engineering defaults, no user decision needed)**:
  - B2: the template RAM cache expires after 60 s, so an upload reaches every instance within a minute.
  - B3: guard every positional read (`lines[i]?.…`). A shifted layout gives blank fields instead of a 500.
  - B6: escape `& < >` in Telegram HTML messages.
  - B8: reject a .docx over 700 KB with a clear Thai message before writing to Firestore.
  - C1: the client sends `system` (`thai_vehicle` / `violation` / `vis`) instead of a Supabase URL.
    The server maps the key to the file and never fetches a client-supplied URL.
  - C2: remove the keep-alive cron route and the `crons` entry in `vercel.json`.
